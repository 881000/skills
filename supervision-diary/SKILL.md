# 监理日志生成技能

## 概述

本技能基于标准监理日志模板，自动生成格式规范的监理日志 docx 文件。核心能力：

1. **模板复刻**：输出与原模板完全一致的表格结构、合并单元格、字体格式（13行×15列合并表格）
2. **内容优化**：对四大业务板块进行专业化语言润色（施工术语、监理用语、问题处理表述）
3. **智能摘要**：内容超限时自动精简，保留关键信息，不丢失施工部位、工程量、质量问题、处理措施等核心要素
4. **自动编号**：核心内容按「1、…。2、…。」格式逐段编号输出
5. **专业排版**：四大板块统一应用固定行距16磅、首行缩进2字符，确保排版规范

## 模板结构

| 区域 | 字段 |
|------|------|
| 表头 | 工程名称、监理日志编号（监理[年份]日志序号号，留空） |
| 基本信息 | 日期（自动计算并在下一行显示星期）、天气（上午/下午）、气温（最高/最低/平均） |
| 核心内容① | 当日施工进展情况（自动优化+摘要+编号+排版） |
| 核心内容② | 当日监理工作情况（自动优化+摘要+编号+排版） |
| 核心内容③ | 当日存在的问题及处理情况（自动优化+摘要+编号+排版） |
| 其他 | 其他有关事项（自动摘要+排版，不编号） |
| 签字 | 监理人员签字、总监或总代签阅（留空） |

## 排版控制规则

### 行数与字数限制

| 板块 | 最大物理行数 | 字数上限 |
|------|------------|---------|
| 当日施工进展情况 | 18行 | ≤600字 |
| 当日监理工作情况 | 6行 | ≤260字 |
| 当日存在的问题及处理情况 | 4行 | ≤160字 |
| 其他有关事项 | 3行 | ≤120字 |

> **注意**：最大行数指Word中显示的物理行数（考虑自动换行），不是段落数。脚本会根据单元格宽度和字号精确估算物理行数，超限时自动迭代压缩。

### 行距设置

四大板块段落行距统一设置为**固定值16磅**（lineRule=exact，line=320二十分之一磅）。

### 首行缩进

四大板块内每段首行设置**缩进2字符**（firstLineChars=200）。

### 智能摘要与物理行数控制策略

当输入内容超出字数或物理行数限制时，按以下策略迭代压缩，确保不超出表单表格限定高度：

1. **物理行数估算**：根据单元格宽度（494磅）、字号（10.5磅五号字）、首行缩进（2字符）、编号前缀（2字符）精确估算每段落在Word中显示的物理行数
2. **合并短句子**：阈值逐步放宽（25→40→55→75→100字），合并相邻短句，合并后单句不超过100字
3. **轻度压缩**：去除冗余修饰词（"非常""及时地""进行了"等），保留核心信息
4. **再次合并**：压缩后对仍较短的句子进行二次合并
5. **删除低优先级**：最多删除1/4的句子，且至少保留2句，按重要性分数（关键词命中数、数字信息、句子长度）从低到高删除
6. **最终截断**：仍超限时截断最后一句并补全句号

**关键原则**：优先通过合并和压缩减少行数，尽量保留施工部位、工程量、监理动作、问题描述、处理措施等核心信息，避免过度压缩丢失关键内容。

## 使用方法

### 快速生成

调用脚本 `scripts/generate_diary.py`，传入各字段参数：

```bash
python3 scripts/generate_diary.py \
  -o 输出文件路径.docx \
  --project "工程名称" \
  --date "2026年8月21日" \
  --weather-am "晴" \
  --weather-pm "多云" \
  --temp-high "32" \
  --temp-low "24" \
  --temp-avg "28" \
  --construction "当日施工进展原始描述..." \
  --supervision "当日监理工作原始描述..." \
  --problem "当日问题及处理原始描述..." \
  --other "其他事项..."
```

### 从文件读取长文本

当内容较长时，可将核心内容分别写入文本文件，用 `--construction-file`、`--supervision-file`、`--problem-file` 参数传入：

```bash
python3 scripts/generate_diary.py \
  -o 输出.docx \
  --project "XX项目" \
  --date "2026年8月21日" \
  --construction-file ./施工内容.txt \
  --supervision-file ./监理内容.txt \
  --problem-file ./问题内容.txt
```

### 全部参数说明

| 参数 | 说明 | 必填 |
|------|------|------|
| `-o, --output` | 输出docx文件路径 | 是 |
| `--project` | 工程名称 | 否 |
| `--date` | 日期（如"2026年8月21日"，**自动计算并在下一行显示星期几**） | 否 |
| `--weather-am` | 上午天气 | 否 |
| `--weather-pm` | 下午天气 | 否 |
| `--temp-high` | 最高气温（数值） | 否 |
| `--temp-low` | 最低气温（数值） | 否 |
| `--temp-avg` | 平均温度（数值） | 否 |
| `--construction` | 当日施工进展情况（原始文本，超600字自动摘要） | 否 |
| `--supervision` | 当日监理工作情况（原始文本，超260字自动摘要） | 否 |
| `--problem` | 当日存在的问题及处理情况（原始文本，超160字自动摘要） | 否 |
| `--other` | 其他有关事项（原始文本，超120字自动摘要） | 否 |
| `--diary-no-year` | 监理日志编号-年份（如"2026"，默认留空） | 否 |
| `--diary-no-seq` | 监理日志编号-序号（如"001"，默认留空） | 否 |
| `--supervisor` | 监理人员签字（默认留空） | 否 |
| `--chief` | 总监或总代签阅（默认留空） | 否 |
| `--construction-file` | 从文件读取施工进展 | 否 |
| `--supervision-file` | 从文件读取监理工作 | 否 |
| `--problem-file` | 从文件读取问题处理 | 否 |

## 内容优化规则

脚本会自动对四大业务板块进行专业化表达优化：

### 当日施工进展情况
- 口语化表述转为工程术语：浇混凝土→浇筑混凝土、扎钢筋→绑扎钢筋、支模→安装模板、挖土→土方开挖等
- 动作表述规范化：做了→完成、搞了→实施、在做→正在进行

### 当日监理工作情况
- 监理动作专业化：看了→巡视检查、查了→检查、验收了→组织验收、旁站了→旁站监理
- 会议与签署规范化：开会→召开会议、签字→签署

### 当日存在的问题及处理情况
- 问题表述规范化：有问题→存在问题、不合格→不符合要求
- 处理措施规范化：让改→责令整改、已改→已整改完成

## 编号规则

1. 输入文本按换行符、中文分号（；）、句号（。）自动切分为独立条目
2. 自动去除输入中已有的编号（如"1、""（1）""一、"等）
3. 每条自动补全句号结尾
4. 统一按「1、…。2、…。」格式重新编号
5. 每个编号条目独立成段，应用固定行距16磅和首行缩进2字符
6. 段落数超过板块最大行数时，自动合并短句或删除低优先级条目
