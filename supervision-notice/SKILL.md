# 监理通知单生成技能

## 概述
本技能基于标准监理通知单模板，自动生成格式规范的监理通知单 docx 文件。核心能力：
1. **模板复刻**：输出与原模板完全一致的表格结构、合并单元格、字体格式
2. **事由优化**：将原始主题描述精简为「关于XXX的事宜」的简短规范格式
3. **内容优化**：对正文进行工程监理专业化语言润色，自动按「1、…。2、…。」逐段编号

## 模板结构
生成的监理通知单包含以下区域（5行×4列合并表格 + 表尾注释）：

| 区域 | 字段 |
|------|------|
| 表头 | 监理通知单（标题，16号加粗居中） |
| 基本信息 | 工程名称、通知单编号（监理[年份]通知序号号） |
| 正文 | 致（施工项目经理部）、事由（自动优化）、内容（自动优化+编号） |
| 签发 | 项目监理机构（盖章）、总/专业监理工程师（签字）、日期 |
| 签收 | 施工单位签收、建设单位签收（各含日期） |
| 表尾 | 注：本表一式三份，建设单位、施工单位、项目监理机构各一份。 |

## 使用方法

### 快速生成
调用脚本 `scripts/generate_notice.py`，传入各字段参数：

```bash
python3 scripts/generate_notice.py \
  -o 输出文件路径.docx \
  --project "工程名称" \
  --notice-year "2026" \
  --notice-seq "001" \
  --contractor "施工单位名称" \
  --subject "事由原始描述" \
  --content "正文原始描述" \
  --deadline "2026年9月5日" \
  --engineer "监理工程师姓名" \
  --date "2026年8月21日"
```

### 从文件读取长正文
当正文内容较长时，可将内容写入文本文件，用 `--content-file` 参数传入：

```bash
python3 scripts/generate_notice.py \
  -o 输出.docx \
  --project "XX项目" \
  --subject "质量问题整改" \
  --content-file ./通知内容.txt
```

### 全部参数说明

| 参数 | 说明 | 必填 |
|------|------|------|
| `-o, --output` | 输出docx文件路径 | 是 |
| `--project` | 工程名称 | 否 |
| `--notice-year` | 通知单编号-年份（如"2026"，对应"监理[2026]"） | 否 |
| `--notice-seq` | 通知单编号-序号（如"001"，对应"通知001号"） | 否 |
| `--contractor` | 致（施工单位/项目经理部名称） | 否 |
| `--subject` | 事由原始描述（将自动优化为「关于XXX的事宜」简短格式） | 否 |
| `--content` | 正文原始描述（将自动优化并按1、2、编号） | 否 |
| `--deadline` | 整改截止日期（如"2026年9月5日"，传入后自动在正文末尾追加整改要求段落） | 否 |
| `--engineer` | 总/专业监理工程师（签字） | 否 |
| `--date` | 签发日期（如"2026年8月21日"） | 否 |
| `--content-file` | 从文件读取正文内容 | 否 |

## 事由（主题）优化规则

1. 自动去除输入中已有的「关于」「的事宜」「的通知」「问题」等套话前缀后缀
2. 提取核心主题内容，限制在30字以内
3. 统一输出为「关于XXX的事宜」格式

**示例：**
- 输入："关于地下室负二层钢筋绑扎质量不合格的相关事宜通知"
- 输出："关于地下室负二层钢筋绑扎质量不合格的事宜"

## 内容（正文）优化规则

### 专业表达优化
- 口语化表述转为工程术语：浇混凝土→浇筑混凝土、扎钢筋→绑扎钢筋、支模→安装模板、挖土→土方开挖、砌墙→砌筑墙体、抹灰→墙面抹灰等
- 监理动作专业化：看了→巡视检查发现、查了→检查发现、有问题→存在问题、不合格→不符合设计及规范要求、没做→未按要求实施
- 处理措施规范化：让整改→责令限期整改、马上改→立即整改、停工→暂停施工、罚款→按合同约定处理

### 编号规则
1. 输入文本按换行符、中文分号（；）、句号（。）自动切分为独立条目
2. 自动去除输入中已有的编号（如"1、""（1）""一、"等）和序列词（首先、其次等）
3. 每条自动补全句号结尾
4. 统一按「1、…。2、…。」格式重新编号
5. 每个编号条目独立成段（docx中换行显示）

### 自动追加整改要求段落
当传入 `--deadline` 参数时，脚本会在正文编号内容之后自动追加一段整改要求：
> 针对上述问题，请贵单位严格按照相关规范及标准要求进行整改落实。整改工作须于{截止日期}前完成，并将书面整改回复报送项目监理部。经监理部复查验收合格后，方可恢复施工。

未传入 `--deadline` 时，则省略日期部分。

### 正文段落格式
正文编号内容及整改要求段落统一设置为：
- 段前：0行，段后：0行
- 行距：1.5倍
- 左缩进（文本之前）：0.5字符
- 右缩进（文本之后）：0.5字符
- 首行缩进：2字符

### 全文字体
文档所有文本（中文、英文、数字）统一设置为**宋体**。
